# Divine 配置试点

真实值位于应用根目录的 `var/config/backend/Function/divine/`，按源码目录对应到 `<代码名>_config.toml`。`config_index.json` 只列文件、字段和使用者，不参与运行时读取。

本目录是可提交的初始模板；首次安装时将需要的文件复制到 `var/config`，不要覆盖已有运行配置。可以通过启动环境变量 `CUO_CONFIG_ROOT` 指定另一配置根目录。配置内的相对资源路径始终相对 cuo 应用根目录，修改配置后重启。

每个 divine 源码文件顶部说明配置来源。配置字段使用 `divine_具体用途` 命名；配置对象使用 `DIVINE_用途_CONFIG`，便于搜索和索引。模型 API 自身的 `max_tokens` 参数及数据库快照中的 `repeat_cost` 保持原协议字段名。

Divine 应事 AI 使用本模块的独立 LiteLLM 地址、模型名称和虚拟 Key，不再使用共享 `ctx.model`。模板中 AI 默认关闭，连接参数留空；在私有配置填入此调用点的专用虚拟 Key 后才能启用。未创建或复制真实密钥。数据库仍使用现有共享配置。纯规则模块无独立小配置。

总索引记录字段说明、敏感属性、可编辑性与重启要求，供后续前端配置管理使用；不存真实值。密钥应在前端以只写字段处理，不回显。本次未增加前端编辑接口。源码顶部统一采用三单引号模块说明，只列用途和配置字段。

配置在模块加载时读取并校验，运行时使用内存对象。缺失配置不会回退模板；启动过程不会写回配置。

独立运行测试时可将 `CUO_CONFIG_ROOT` 指向本目录，以使用模板配置。
