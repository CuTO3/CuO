# Divine · 占卜模块

本文按 2026-10-29 本地代码整理。描述模块实际实现，不代表同版本已部署到生产服务器。

## 产品定位与文案原则

第一原则是有趣。周易提供传统仪式感与可理解的判断，应事将卦意落到真实群聊中的具体事情，塔罗牌图提供视觉吸引力，福缘使占卜产生实际数值影响。

- 卦题、解卦、签语：庄重、凝练，解释局面与转折，避免晦涩堆砌及“这卦提醒你”等说教套话。
- 应事：自然随意，可适度打趣；必须说明真实小事与卦意的联系。
- 不编造经历、次数、输赢、承诺或未回复等细节；群里话题不能直接写成请求者亲历。
- 有变卦时，解释本卦、变化关节及后势；不能只在标题挂一个变卦名。
- 不制作整张签图。采用 QQ 普通文字与原塔罗牌图混排。

## 当前实现概览

| 部分 | 实现 |
| --- | --- |
| 起卦 | 三枚钱币法，六次得到六爻；使用系统随机源 |
| 固定解卦 | `readings.json` 覆盖 4096 种本卦与动爻组合 |
| AI 职责 | 只生成与真实聊天相关的应事，不生成解卦或决定分数 |
| 卦运 | 新卦读取固定记录中的方向和幅度范围，再随机确定数值 |
| 再次占卜 | 同群、同用户、同业务日首次免费，其后每次消耗 2 点福缘 |
| 历史结果 | 已保存结果直接返回，不因资料升级重新抽卦或结算 |
| 塔罗视觉 | 当前仍使用 `Tarot -version-Arknight` 的文件映射 |
| TrueDark | 素材已整理，尚未接入 `tarot_image.py` |

## 一次占卜的处理路径

1. 按任务 ID 查询已完成结果；存在时直接返回，避免重复结算。
2. 以群、用户、业务日获取事务锁，查询当日占卜。
3. 若已有其他任务正在生成，返回“这卦还在算，稍等一下喵。”。
4. 若当日已有成功占卜，锁定成员余额并检查是否足够支付 2 点福缘。
5. 起卦、选择固定解读、确定卦运和塔罗，将随机结果、解读快照与版本写入草稿。再占费用与草稿在同一事务保存。
6. 从前一个业务日、且消息 ID 不超过触发快照的聊天中提取应事候选，调用模型或采用固定兜底。
7. 锁定占卜记录和成员，应用本次卦运，保存完整结果与任务结果，再交给发送链路。

业务日期统一使用北京时间凌晨 04:00 为分界。占卜记录与福缘以 PostgreSQL 为准，文件缓存不决定结算。

### 再占费用与提示

```text
首次占卜：结算后福缘 = 结算前福缘 + 卦运
再次占卜：结算后福缘 = 起卦前福缘 - 2 + 卦运
```

再占费用在创建草稿时扣除，模型调用在事务之外。生成中断后重试同一任务会复用草稿，不再扣费；当前没有为永久失败草稿自动退款的流程。

- 再占成功时，消息前加“往日福缘深厚，尚可再问天机。”，不直接显示消耗数字。
- 福缘不足时，先发送“今日缘法已尽，且待明日再问。”，再附上当天最新一次成功占卜及可用牌图。
- 当前再占提示只加在发送内容上，数据库 `content` 保存占卜正文；不足时回显的是该正文。
- 吉卦也可能因再占费用净减福缘，例如卦运 +1、费用 2，净变化为 -1。

## 固定解卦资料

### 两层数据

`hexagrams.json` 保存 64 卦及其卦辞、六爻爻辞、用九/用六等原文，并新增 `reading_title`、`interpretation`、`theme`。文本已转为简体，保留“乾”等易学用字；原始来源与校验值的含义见 `data/SOURCES.md`。

`readings.json` 当前版本为 `readings-v1`，顶层包含 `version`、`editorial_status` 和 `readings`。组合键是“本卦编号:从下向上的动爻位置”，例如：

```text
11:0       泰卦，无动爻
11:3       泰卦，九三动，变临卦
11:1,3     泰卦，初爻与三爻动
```

六爻各有动、静两种情况，64 个本卦各有 64 种组合，共 4096 条。

| 记录字段 | 用途 |
| --- | --- |
| `key`、`base_number`、`moving_lines`、`changed_number` | 唯一定位组合 |
| `title` | 标题中卦名之后的卦题 |
| `primary`、`auxiliary` | 主断辞、辅助断辞及原文来源 |
| `interpretation` | 固定解卦正文 |
| `fortune` | 吉凶档位、方向、幅度范围与判定线索 |
| `theme` | 提供应事的主题方向 |
| `closing` | 收尾签语 |
| `fallback_advice` | 无聊天依据或模型失败时的应事文案 |
| `version`、`editorial_status` | 版本及编排状态 |

`fortune.direction` 为 -1、0、1，`magnitude_min` 与 `magnitude_max` 是非负幅度。运行时先取原随机权重的绝对值，再限制在记录指定范围内；这并非范围内均匀抽样。

### 主断辞选择

资料生成时按 `dictum.py` 的现有规则选择：

| 动爻数 | 主断辞 | 辅助断辞 |
| --- | --- | --- |
| 0 | 本卦卦辞 | 无 |
| 1 | 本卦该动爻 | 无 |
| 2 | 本卦位置较高的动爻 | 位置较低的动爻 |
| 3 | 本卦卦辞 | 变卦卦辞 |
| 4 | 变卦位置较低的未动爻 | 位置较高的未动爻 |
| 5 | 变卦唯一未动爻 | 无 |
| 6 | 乾坤取用九/用六，其余取变卦卦辞 | 乾坤另附变卦卦辞 |

这是本项目采用的选择规则，不代表所有周易解释流派的统一规定。

### 吉凶与“无咎”

新卦以固定记录的 `fortune` 为准，不由模型现场改判。初版资料生成时使用 `luck.py` 的上下文线索规则：无咎表示免于过失，不自动抹去凶险；单独无咎可以为平，吉无咎偏吉，厉无咎偏凶，厉终吉可转吉。

| 初版档位 | 卦运范围 |
| --- | --- |
| 小吉、转吉 | +1～+3 |
| 吉 | +2～+6 |
| 大吉 | +4～+10 |
| 小凶 | -3～-1 |
| 凶、转凶 | -10～-4 |
| 平、吉凶参半 | 0 |

这些是游戏结算规则。记录可以单独修订，不能以是否含有“吉”字作为所有断辞的唯一标准。

**当前限制：** `luck.py` 同时供生成器使用，并仍作为 `draw_dictum_luck()` 缺少 `reading_fortune` 时的兜底；正常新卦已提供固定范围。运行时兜底尚未迁移为纯离线工具。

### 校订、生成与生效

目录初版标记为 `initial_rule_composed`：以固定卦义、主断辞规则、爻位和吉凶档位编排，含泰九三等专项解读。覆盖完整不等于 4096 条都已逐条人工校订，复杂条件断辞及多爻解释仍需细校。

可直接修订某条记录的解卦、卦题、签语与福缘范围。生成器当前没有单独的人工覆盖文件，重新生成会覆盖对 `readings.json` 的直接修改，执行前须保留校订内容。

在项目根目录（含 `pyproject.toml`）运行：

```powershell
$env:PYTHONPATH = 'src/backend'
python -m ops.build_readings
```

进程会缓存解卦目录；更新文件后需重启服务，新任务才会读取新版本。新卦将完整记录保存到 `zhou_yi.reading`，已生成草稿与历史结果不随目录修改重算。

## AI 应事与兜底

候选取自前一业务日聊天，排除机器人消息与对机器人的直接请求。优先匹配配置短语，否则取名词；根据本人发言、对本人的回复、群内参与情况等评分，最多保留 5 个候选。

模型输入包含固定解卦、主题、主断辞、塔罗、卦运及候选证据。输出只允许：

```json
{"keyword": "候选主题", "refs": ["m00001"], "advice": "联系卦意的具体应事"}
```

- `keyword` 必须原样选中候选；非空 `refs` 必须来自该候选。
- `advice` 校验为 15～100 字；提示词建议约 40～80 字。
- 最多尝试两次，每次超时 30 秒。
- 无候选不调用模型；模型失败、校验失败或主动弃选时，使用固定记录的 `fallback_advice`，主题为“今日一应”，`refs=[]`。
- 代码校验证据引用及字段格式；应事的语义相关性与是否充分忠于材料仍需抽查。

## 标准消息模板

模板来自 `merge_message.py`；图片由 `tarot_image.py` 插入。下列点号表示字典字段路径。

```text
{zhou.base.symbol/本卦符号} {zhou.base.name/本卦名称} → {zhou.changed.symbol/变卦符号} {zhou.changed.name/变卦名称} | {reading.title/固定卦题}

塔罗｜{tarot.name/塔罗牌名} · {tarot.orientation/正逆位}
{image消息段/真实塔罗牌图}

「{reading.primary.text_display/主断辞}」

解卦
{reading.interpretation/固定解卦内容}

应事 · {ai.keyword/应事主题}
{ai.advice/应事内容}

卦运 {luck_delta/本次卦运，正数带+号} · 福缘 {fortune_after/结算后福缘}

{reading.closing/固定收尾签语}
```

无变卦时省略箭头与变卦。动爻仍保存在数据中，消息首行不单列“九三动”等信息。普通文本不依赖 Markdown 加粗和标题渲染；QQ 客户端决定字体、字号和自动折行。

## 塔罗牌与图片

`tarot.py` 使用有变化时的变卦、否则使用本卦，按上卦选择三张候选牌，再以动爻数模 3 选一张。当前映射覆盖 18 种牌，并未覆盖全部 22 张。卦运非负为正位，负数为逆位；塔罗不独立决定福缘。

`tarot_image.py` 当前硬编码读取 Arknight，并按牌名映射现有 8 张素材。缺少映射或文件时退回纯文字；逆位旋转 180°，以 PNG 编码为 OneBot image 消息段，插入塔罗标题之后。

TrueDark 根目录的标准 22 张大牌及英文补充包已整理，主要扫描尺寸为 550 × 984；这只是素材准备完成。更换默认牌组还需要修改图片选择逻辑，不能只把文件放进目录便认为已启用。切换时应按牌名对应，注意 Arknight 与 TrueDark 的力量/正义编号差异，模型牌名“星星”与文件名“星”也需映射。

图片来源、原作者及使用条件应随素材保留；图鉴公开展示不自动构成再分发授权。
