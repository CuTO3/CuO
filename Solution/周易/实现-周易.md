# 周易

> 最新接口约定：数据结构以 `../府库/实现-府库.md` 为准。卜算保存于 divinations，累计福缘保存于 members.fortune，任务及发送状态保存于 log；不再建立 divine_records、fortune_accounts、fortune_ledger 或 outbox。结算事务同时更新 divinations、members 和业务日志。返回包含 send_message 的 actions 列表，由 Main 统一发送，替代下文初稿的 reply_text/delivery_owner。business_date 为只含年月日的 DATE，仍按 04:00 日界计算。

## 1. 模块综述

`divine.py` 负责一次完整卜算：检测今天是否已经占卜，生成本卦与变卦，取得塔罗和周易原文，结合昨日聊天生成生活化解读，结算福缘并保存结果，返回 Main 发送。

未实现。本文件先补齐设计实现路径，再逐项讨论。已定规则作为约束；起卦方法、取辞法、塔罗对应、关键词评分和失败文案等明确标为“初稿方案”，不宣称已经确认或完成测试。

### 1.1 已定规则

- 接收 group_id、user_id，以稳定用户 ID 查询记录，数据按群隔离。
- 模块名除 AI 外全部小写；提示词与示例单独放入 prompts。
- 展示卦象字符、卦名、动爻及是否变卦、对应塔罗牌和正逆位、周易原文。
- 结合昨天聊天中的生活关键词，如大龙玉、排位连跪，生成约 30 字的轻松解读。群友图一乐，不写工作汇报或严肃预测。
- 卦运与累计福缘放在消息最下面，使用这两个名称。
- 福缘初始值为 0；一次卦运为 -10～+10 的整数，概率按第 9 节执行。
- 今天已经占卜过则不重新生成、不重新结算，回复提示。
- 保存卜算结果、福缘明细和累计福缘时使用同一个数据库事务；发送失败只恢复发送。

日期沿用项目统一业务日：北京时间当天 04:00 至次日 04:00，昨日也按业务日计算。

## 4. 执行路径

```text
检查输入、确定业务日期
→ 按 task_id 查询已有草稿或成功结果
→ 检查本群该用户当天是否已有成功结果
→ 建立或恢复当天卜算草稿
→ zhou_yi 生成六爻；抽取卦运；立即保存随机结果
→ tarot 取得对应卡牌；dictum 查原文
→ 查询昨日聊天，构建有证据的关键词候选
→ AI_divine 选择关键词并生成约 30 字短解读
→ 读取并锁定当前福缘，计算结算后数值
→ merge_message 拼成最终消息
→ 同一事务：保存成功结果、插入福缘明细、更新累计福缘
→ 提交成功后返回 Main
→ Main 持久化发送任务并发送
```

模型调用和 QQ 发送都在数据库事务外。只有最终结算阶段短暂锁定福缘行，不在等待 DS 时占用行锁。

## 5. zhou_yi.py：起卦初稿

### 5.1 六爻生成

初稿采用三枚等概率二值随机数相加的方法。每枚取 2 或 3，各 1/2；每爻独立抽三次，得到 6、7、8、9。连续生成六爻，从下往上保存。

| 爻值 | 本卦 | 是否变化 | 变卦 |
|---|---|---|---|
| 6 | 阴，0 | 是 | 阳，1 |
| 7 | 阳，1 | 否 | 阳，1 |
| 8 | 阴，0 | 否 | 阴，0 |
| 9 | 阳，1 | 是 | 阴，0 |

对应概率为 1/8、3/8、3/8、1/8。此处是明确的项目起卦实现选择，不声称所有传统起卦方法都使用同一分布。

生产随机源初稿使用系统随机源；测试允许注入固定序列。每个草稿只生成一次，后续重试读取 line_values；禁止根据 user_id、日期或福缘自行重新推导随机种子。

### 5.2 卦象查表

hexagrams.json 保存 64 条：number、name、short_name、symbol、bits_bottom_up、lower_trigram、upper_trigram、judgment、lines、special_text、source_url、text_version。

卦序不是二进制整数顺序，必须通过 bits_bottom_up 查表。Unicode 字符按文王卦序使用 `chr(0x4DC0 + number - 1)`，并与资料逐条验证。[Unicode 官方卦象字符表](https://www.unicode.org/charts/PDF/U4DC0.pdf)

无动爻时 changed 保存与 base 相同的对象，has_change=false；展示只写本卦和“无变卦”，不画重复箭头。有动爻时必须发生 bits 变化。

启动校验：64 个卦序、64 个六位码都唯一且完整；每卦六条爻辞齐备；缺失资料禁止启动占卜模块，不能让 AI 临时补齐。

## 6. dictum.py：覆盖所有取辞情况

### 6.1 原文库

从校对过的周易原文构建本地资料，不在每次请求时联网查句子。原文和供展示的简体文本分别保存；转换只改繁简，不改写句意。参考乾上九原文“亢龍有悔”，展示可用“亢龙有悔”。[中国哲学书电子化计划：乾上九](https://ctext.org/text.pl?if=en&node=25022&show=parallel)

每条语录包含 text_original、text_display、hexagram_number、line_position（卦辞为 null）、source_label、source_url。现代翻译、编辑注释和 AI 解读不混入原文。

### 6.2 多动爻规则初稿

以下为本项目的固定取辞方案，供后续讨论；不宣称是唯一传统规则。规则返回一条主引文和零条或多条辅助引文，群消息只显示主引文，完整资料保存到数据库供详情查看。

| 动爻数量 | 主引文 | 辅助引文 |
|---|---|---|
| 0 | 本卦卦辞 | 无 |
| 1 | 本卦该动爻爻辞 | 无 |
| 2 | 本卦两个动爻中位置较高者的爻辞 | 较低者爻辞 |
| 3 | 本卦卦辞 | 变卦卦辞 |
| 4 | 变卦两个未动位置中较低者的爻辞 | 较高者爻辞 |
| 5 | 变卦唯一未动位置的爻辞 | 无 |
| 6，纯乾全动 | 本卦用九 | 变卦卦辞 |
| 6，纯坤全动 | 本卦用六 | 变卦卦辞 |
| 6，其余 | 变卦卦辞 | 无 |

“高/低”均按初爻=1、上爻=6。四、五动爻时，“未动位置”指原卦中没有变化的位置，取的文字来自变卦。不再额外随机挑选好听的语录。

主引文不按字数硬截断，也不让 AI 缩写。若原文较长，完整显示；以后若要节选，应另建经过校对的 excerpt 字段，不能执行模块自己删句。

### 6.3 穷举校验

遍历 64 本卦 × 64 动爻位掩码，共 4096 种状态。每种验证：变卦存在、主引文非空、来源正确、辅助引文顺序稳定、用九/用六分支只出现在对应状态。还需独立人工核对每种动爻数量的代表案例，不能只用同一算法生成期望值后自证正确。

## 7. tarot.py：塔罗对应初稿

周易与塔罗不存在本项目已确认的权威一一对应。本稿使用明确的娱乐映射，不把人为关联描述为传统定论，也不再抽一次随机牌。

先取“有变卦则变卦、无变卦则本卦”的上卦，按下表选择三张候选；再以 `len(moving_lines) % 3` 作为下标（从 0 开始）选牌。

| 上卦 | 候选0 | 候选1 | 候选2 |
|---|---|---|---|
| 乾 | 皇帝 | 战车 | 太阳 |
| 坤 | 皇后 | 世界 | 节制 |
| 震 | 高塔 | 愚者 | 战车 |
| 巽 | 魔术师 | 恋人 | 星星 |
| 坎 | 月亮 | 隐者 | 倒吊人 |
| 离 | 太阳 | 正义 | 审判 |
| 艮 | 隐者 | 力量 | 节制 |
| 兑 | 星星 | 命运之轮 | 皇后 |

正逆位初稿由卦运方向确定：卦运 ≥ 0 为正位，< 0 为逆位。这里是项目展示规则，不意味着所有逆位牌都不吉；不重写牌名，也不让 AI 更换正逆位。

因此接口为 `map_tarot(zhou_result, luck_delta)`，返回 card_id、name、orientation、mapping_version。映射文件必须穷举八个上卦及三种候选下标；本方案没有声称覆盖整副 78 张牌。

正逆位与卦运绑定为初稿选择。后续若改用其他规则，提升 mapping_version；已经保存的结果不随配置变化重新算牌。

## 8. 昨日素材与 AI_divine

### 8.1 素材选择初稿

只读本群上一业务日的消息，不读其他群。首次准备草稿时保存查询快照序号，此后重试复用，避免不断变化的上下文。优先用户本人发言、明确回复该用户的讨论；本人没有可用话题时允许取群话题，但不能写成用户亲历。

直接复用众声录的身份标准化与图片文字缓存，不重新识图。排除机器人卜算、福缘通知、旧总结和请求命令；健康、法律、投资等严肃决定不作为娱乐建议的主题，候选不足则使用生活兜底。

keyword_rules.json 初稿含领域短语及停用词；以最长词优先提取“大龙玉”“排位连跪”“怪物猎人”“PPT”等完整词。未命中词典的名词短语用本地分词候选，不让模型凭空生成昨日事件。

每个候选保存 keyword、refs、speaker_relation、source_excerpt。初稿评分为：本人提到 +4；明确回复本人 +2；包含失败/没出/连跪等受挫表达 +2；每个不同发言人提及 +1，上限3。按分数降序、最近出现时间降序、关键词字典序排序，取前5个；每个保留前后各1条相关消息，总素材最多20条，每条最多200字符，截断标记明确。

本人同一语句符合多个条件可相加；计数按 message_id 去重。泛词“今天”“这个”“东西”在停用词表中。候选评分规则及词典是初稿，随后用真实聊天验证。

### 8.2 AI 标准输入输出

```python
async def generate(zhou_result: dict, tarot_result: dict, dictum_result: dict,
                   candidates: list[dict], luck_delta: int) -> dict:
    ...
```

模型只返回：

```json
{
  "keyword": "大龙玉",
  "source_refs": ["m013", "m016"],
  "advice": "昨夜没出玉，今天叫上群友刷三把；还不出就先吃饭，别把晚饭也刷没了。"

```

keyword 必须来自候选列表；source_refs 必须引用该候选已有证据。没有素材时 keyword 固定为“今日小事”、source_refs=[]。advice 初稿目标 24～40 个可见字符（含标点，不计换行）；不得包含卦运数字、福缘、伪造周易原文或自行改牌。校验失败修复一次，再失败使用固定兜底。

每次 DS 调用超时 30 秒；网络重试一次。格式/长度/引用错误修复另限一次，整个 AI_divine 阶段最多3次调用。失败时保存 generated_mode=fallback，不把模型失败当作已经成功返回。

## 9. 卦运分布与累计福缘

### 9.1 最终已定离散概率

基础权重 `b(x)=exp(-x²/18)`，x 为 -10～10 的整数。先令 `w(0)=b(5)`；令 ±1、±2、±3 六个值的权重都等于 `(b(1)+b(2)+b(3))/3`；其他值仍取 b(x)。最后除以总权重归一化。

| 卦运值 | 每个值的概率 |
|---|---:|
| -10、+10 | 各 0.0571379208% |
| -9、+9 | 各 0.1641898801% |
| -8、+8 | 各 0.4221953020% |
| -7、+7 | 各 0.9714612112% |
| -6、+6 | 各 2.0002422227% |
| -5、+5 | 各 3.6854012080% |
| -4、+4 | 各 6.0761993627% |
| -3、+3 | 各 11.5934907628% |
| -2、+2 | 各 11.5934907628% |
| -1、+1 | 各 11.5934907628% |
| 0 | 3.6854012080% |

这是调整后的离散分布，不再称为标准差为3的正态分布；3只是构造初始权重的参数。表格仅供显示，实际抽取使用未四舍五入权重。

初稿实现按 x 从 -10 到10 构建累计概率，用随机 u∈[0,1) 选择第一个累计概率严格大于 u 的值。最后一项边界强制为1，防止浮点误差漏选。保存 luck_delta 和 luck_version，重试不重新抽取。

### 9.2 卦运与卦象的关系

初稿将卦运作为独立游戏分数，与六爻使用不同随机抽样，避免人为调整卦象破坏起卦概率，也避免依据卦辞评分后破坏已确认的离散概率。卦辞不等于单一吉凶分值；展示不额外加“大吉/大凶”标签。AI 可以同时参考它们，但不能为了匹配数字改原文。

这属于需要下一轮讨论的设计选择。若要求分数与卦义严格一致，必须另外设计联合分布，不能直接把64卦任意分档后宣称仍符合本表。

### 9.3 累计

```text
初始福缘 = 0
新福缘 = 旧福缘 + 本次卦运
```

初稿累计允许负数、不设上下限、不影响下一次抽取概率。-10～+10 只约束本次卦运，不能把累计福缘也截断到此区间。负数和上限属于待逐项讨论的初稿选择。

## 10. 数据库及每日检测

### 10.1 表结构初稿

| 表 | 关键字段和约束 |
|---|---|
| divine_records | id UUID；`(group_id,user_id,business_date)` 唯一；origin_task_id 唯一；status；line_values/zhou/tarot/dictum JSONB；luck_delta；keyword、source_refs、advice；luck_before/after；body；所有规则版本；created_at、settled_at |
| fortune_accounts | `(group_id,user_id)` 主键；balance bigint 默认0；version；updated_at |
| fortune_ledger | id UUID；divine_record_id 唯一；group_id、user_id、business_date；before、delta、after；created_at；CHECK after=before+delta |

divine_records 状态为 preparing、ready、settled、failed_retryable、needs_review。preparing/ready 是草稿，不算已经完成占卜；settled 才会产生福缘明细。数据库唯一约束防止后续误开多个 worker 时重复结算，日常执行仍然串行。

### 10.2 检测和恢复

1. 相同 task_id 已 settled：返回原结果，交 Main 按 outbox 去重恢复发送。
2. 不同 task_id 发现当天 settled：返回“今日已占卜，明日再来喵。”，不返回一份新结果。
3. 当天已有未完成草稿：原任务正在运行则回复“这卦还在算，稍等一下喵。”；原任务明确失败且无活动租约则恢复同一草稿，不另建随机结果。
4. 草稿中的六爻与卦运已保存后，任何失败都不能重抽。模型失败按兜底继续；原文缺失、查表错误和数据库异常不能使用兜底伪造成功。
5. 同一日失败恢复使用原 business_date；不能因为恢复时到了次日就把它计入次日。

草稿和恢复任务使用同一 record_id；最终发送动作的稳定关联键使用 record_id，任务恢复时不能因 task_id 改变导致再次发送同一结果。

### 10.3 最终事务

```text
BEGIN
→ 锁定 divine_records 行并检查未 settled
→ 初始化或取得 fortune_accounts 行并锁定
→ 读取当前 balance；计算 before、delta、after
→ 用这些数值拼接最终 body
→ 写 fortune_ledger（divine_record_id 唯一）
→ 更新 fortune_accounts.balance
→ 更新 divine_records 为 settled，并保存完整结果与 body
COMMIT
```

任一步失败全部回滚。已保存的随机草稿保留，可恢复。提交成功后才能发送成功消息；发送失败不回滚福缘，也不再执行上述加分事务。

## 11. merge_message.py：标准化输出

输入 zhou、tarot、dictum、AI_result、luck_delta、fortune_after，输出纯文本。每段顺序固定：

```text
{本卦符号} {本卦名} → {变卦符号} {变卦名}
{动爻文字} · 有变卦
塔罗｜{牌名} · {正位或逆位}

「{主引文原文展示值}」

今日应事 · {关键词}
{约30字短评}

卦运 {带符号增减值} · 福缘 {累计值}
```

无变卦时第一行只显示本卦，第二行“无动爻 · 无变卦”。爻位名称按本卦阴阳生成：第一位初六/初九，二至五位六二/九二等，第六位上六/上九；多个动爻按位置递增以顿号连接。卦运正数加 `+`，负数使用负号，0显示 `0`。

下面是与本稿初稿映射一致的演示，不是实际抽签结果：

```text
䷀ 乾为天 → ䷪ 泽天夬
上九动 · 有变卦
塔罗｜命运之轮 · 逆位

「亢龙有悔。」

今日应事 · 大龙玉
昨夜没出玉，今天叫上群友刷三把；还不出就先吃饭，别把晚饭也刷没了。

卦运 -3 · 福缘 68
```

该例假定结算前福缘71，本次-3，因此结果68。它替代早期仅示意排版的牌面组合；真实运行只使用数据结果，不硬编码演示数字。消息元数据由 Main 标记 generated_by=divine，便于众声录默认过滤。

## 12. 失败处理与版本

| 失败 | 动作 |
|---|---|
| 无昨日聊天 | 今日小事兜底，不捏造个人经历 |
| DS 超时或不合格 | 限次重试后固定短评，标明内部 fallback |
| 原文资料缺失、卦码不匹配 | 中止，不结算，不交 AI 补文 |
| 福缘事务失败 | 回滚结算，保留随机草稿 |
| QQ 明确发送失败 | 只恢复发送 |
| QQ 是否已发送不明 | outbox 标记 unknown，人工核查，禁止盲目重发 |
| 用户当日重复请求 | 固定已占卜提示，不重抽、不再增减 |

保存 zhou_version、dictum_version、tarot_version、luck_version、keyword_version、prompt_version、model。历史记录使用当时快照，不随配置更新改写。数据变更必须先通过校验再启用新版本，不能在半次卜算中混用新旧规则。

## 13. 验收

1. 固定 line_values=[7,7,7,7,7,9]，得到乾→夬、上九动、主引文来自乾上九。
2. 无动爻显示“无变卦”；六爻全6和全9分别触发规定的特殊取辞分支。
3. 穷举4096状态，查表、变卦和取辞均无缺口；完整爻值状态恰为4⁶种，与该穷举一一对应。
4. 概率总和误差≤1e-12；P(x)=P(-x)；P(0)=P(5)=P(-5)；±1、±2、±3六项相同。
5. 使用边界 u 值测试累计抽样落点；统计抽样仅作补充，不替代概率表的数学校验。
6. 新用户balance=0，抽到-3后为-3（初稿允许负值），抽到0也保存一条delta=0明细并占用当日次数。
7. 同一记录重复提交事务只产生一条 ledger；消息重发不再次加分。
8. 03:59:59和04:00的业务日期不同；跨日排队仍按原触发日期。
9. 昨日只有别人刷素材时，AI不能写成“你昨夜没出玉”；没有素材不得编造关键词来源。
10. 游戏素材示例保持约30字，原文、牌名、卦运和累计值均不由 AI 决定。
11. 准备阶段宕机恢复后六爻、卦运不变；结算后宕机恢复不再产生第二次福缘变化。
